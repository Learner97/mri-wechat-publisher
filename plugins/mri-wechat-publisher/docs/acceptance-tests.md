# 第一阶段验收测试

## 本地测试

- [ ] 示例 JSON 通过结构校验。
- [ ] 缺失五个固定章节时校验失败。
- [ ] 单篇论文标题未严格使用唯一的“期刊全名或公认缩写 | 内容主标题”结构（包括出现多个 `|`）时校验失败。
- [ ] ` | ` 后的内容主标题超过 20 个字符时校验失败；期刊标识和分隔符不计入这 20 个字符。
- [ ] 完整标题超过微信字段上限 64 个字符时校验失败。
- [ ] 未记录 DOI 或来源标识时校验失败。
- [ ] `publish`、`freepublish` 或 `mass_send` 自动动作被拒绝。
- [ ] HTML 不包含脚本、表单、事件属性和外链样式表。
- [ ] 输出包含标题、摘要、五个章节和参考文献。
- [ ] 旧 JSON 状态可一次性迁移到 SQLite，迁移后完整性与外键检查通过。
- [ ] 同一时刻只能存在一个活动周期；已选择论文、5轮冷却候选和重复任务运行键被拒绝。
- [ ] 未选论文在后续5个推荐轮次不可再次出现，并可在第7轮（间隔5轮后）重新进入候选。
- [ ] `select-order --choices 2,3` 按指定顺序建立队列，前一篇保存草稿后自动激活下一篇。
- [ ] 排队论文在 `available_at` 之前返回 `queued_not_ready`，不会因09:30每日检查而破坏隔日成稿节奏。
- [ ] `SELECTED → WRITING` 由 `claim-writing` 原子完成，竞争任务不能重复领取。
- [ ] 选文、成稿、草稿批准、草稿回执、人工发表和统计快照可完成端到端状态流转。
- [ ] 每次事务提交后兼容 JSON 快照可重新生成，且不包含任何凭据。

## API 测试

- [ ] `.env` 仅验证变量存在，不输出值。
- [ ] 获取稳定凭据成功。
- [ ] 上传正文图片和封面成功。
- [ ] 新增草稿成功，或明确记录无权限错误并切换备用通道。
- [ ] 没有调用发布或群发接口。
