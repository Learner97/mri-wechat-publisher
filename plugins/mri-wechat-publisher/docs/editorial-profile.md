# 文献与方法融合文章规范

## 适用范围

本规范用于依据已核验的正文、补充材料、附录、图注、proof及其他版本等研究材料，撰写 MRI、认知神经科学及相关医学或生物学研究解读。文章整合材料后客观复述研究问题、方法和结果，并只解释需要说明的结果，不暴露检索、核查或材料比较过程，也不扩写为通用方法教程。

新文章使用 `schema_version: 8`。历史 `schema_version: 1` 至 `schema_version: 7` 文章仅为兼容读取、渲染和草稿上传，不再作为新文章模板。

## 标题

- 使用“期刊全名或公认缩写 | 简短内容题眼”结构。
- ` | ` 后的题眼以不超过24字符为偏好，超出只提示精简；完整标题仍不得超过64字符。保留对象、效应方向和必要限定，不能为满足偏好长度压缩成不准确的结论。
- 期刊名称、对象及发现必须一致。关联不写成因果，影像分型不等同临床分型，相对保留不写成完全不变，探索预测不写成成熟工具；“证明、决定、重定义、首次发现”等强措辞须有对应来源。

## 正文结构

正文必需部分采用以下顺序，参考文献置于文末但不另计正文节：

1. **研究速览**：用不固定的短篇幅交代研究问题、研究对象、分析框架和核心结果等必要信息；这些是方向而非固定字段。具体 t、p、OR、β 等统计量留给结果，不与 digest、引言和结语反复完整陈述同一结论。
2. **引言**：按照“已知—既往发现—未知—既往不足”的逻辑交代背景，只保留理解研究问题所需内容。研究速览已经说明研究设计和核心结果时，引言不再重复样本、分析顺序和结论。
3. **方法**：突出分析思路、关键步骤和核心参数。软件版本、命令选项、追踪步长、流线长度与数量等完整细节保留在内部 `method_map`；正文只保留定义核心分析、影响结果解释或理解后续指标的部分。
4. **结果**：默认遵循原论文 Results 顺序，描述与研究问题和中心结论有关的全部必要结果。只保留决定主要结论成立与否的统计量，次要 p 值、OR、β、置信区间和富集条目可按方向、范围或主题概括。
5. **结果解读**：解释结果意味着什么、不同结果如何联系以及哪些解释范围确实影响理解。不复制结果段落，不把相关、空间对应、PLS或基因富集写成直接因果或机制证据，也不机械添加免责声明。
6. **结语**：仅说明新增的具体认识或方法证据，优先一段。删除没有信息增量的“提供新框架/新视角”“从A到B的转变”；不重复主要数值、方法流程和全部局限。方法或设计层内容是可选项，只在能增加论文特异性信息时自然写入；不默认生成第二段，不重复方法流程、全部结果和详细统计，不单独设置“方法启示”，不进行证据或价值排名。

修改现有稿件时，先锁定用户未要求修改的章节。修改优先采用删除多余表达、保留自然原句、调整句序和衔接、局部补充解释，只有前述方式无法解决时才重写句子。

结果数量由原文决定，不预设“三项”“五项”或其他数量。结果小标题直接说明实际比较或发现，不使用“关键结果”“核心发现”“证据一”等泛化标签。

## 方法与结果的取舍

- 新文章必须建立内部 `method_map`，按 `core`、`supporting`、`routine` 标记方法重要性，记录分析目的、数据、处理、统计、必要输出和研究材料定位。正文不显示字段标签。
- 数据信息优先包括样本量和来源、模态、训练/测试/参考样本、分析单元及来源支持的矩阵维度。
- 内部处理信息可完整记录软件和版本、预处理、分区、指标计算、模型输入、算法和参数；公开方法正文按重要性压缩，只保留核心分析逻辑、关键步骤和决定性参数。
- 统计信息优先包括模型、协变量、相关方法、多重比较、交叉验证、bootstrap、permutation、spin或空间零模型、阈值、稳健性与外部验证。
- 输出仅在有助于理解后续分析、矩阵结构或变量定义时说明，不要求每个分析单独总结输出。
- 方法先服务于理解本研究；只允许对易误解概念作一至两句直接解释，不写成对其他研究者的操作指南。
- 核心与创新方法说明输入及分析单位→数学/计算操作→输出指标/矩阵/模型→后续检验怎样使用该输出。关键维度、对角线、归一化、投影或独立计算、验证划分须与来源一致；标准预处理、常规富集和次要敏感性分析明显压缩。网络权重不自行解释为实际能耗，静态差异不解释为变化速度。
- 只有定义核心分析、改变输出或影响结果解释的参数进入正文。成熟标准 pipeline 已经命名后，其内部常规步骤无需展开成软件与参数清单。
- 常规未报告参数默认省略且不主动说明。只有缺失信息直接影响主要结论解释，或用户明确要求审查方法完整性时才指出。
- 结果说明分析对象、观察到的变化、决定结论成立与否的关键数字或图表以及直接含义；避免连续堆积多个校正 p 值、OR 或 β。
- 机制解释和研究范围只在影响理解时进入结果解读，不混入结果；临床或因果外推不得超出研究材料。
- 默认只写研究实际测量和分析的内容，不列举未使用的指标、未纳入的变量、未测量的数据或未执行的验证。只有缺失内容会造成中心结论的具体误读、研究材料把它作为必要解释条件，或用户明确要求局限/完整性审查时才说明。
- 必要范围说明与其限定的主张放在一起，并优先改写为对实际变量、数据来源或分析单位的正面定义；不在段尾连续追加“未测量”“未纳入”“没有检验”“无法回答”等免责声明。
- 方法评价、迁移建议、观测结果和研究限制分别留在合适章节；一般性评论不得压过论文的具体操作和结果。

## 篇幅与配图

不设置正文总字数、结果数量、段落数量或章节比例的硬限制。研究速览保持紧凑但不设字数阈值；结果解读的深度由需要解释的关系决定；结语说明主要认识后即可结束，不强制补充方法学价值。

图片数量由解释需要决定，不固定为 5–8 张。封面和正文只能使用当前论文正文或补充材料中实际出现的原图，不生成、重绘、仿制、改色、信息图化或使用图库、装饰图；这与论文访问状态、许可类型无关。优先用支持主要分析的核心结果图，不因为补充图更简洁就用数值不同的敏感性分析替代主结果；确有需要时在相邻正文和图注说明区别。

- 优先取出版商最高可读分辨率原图或登记源文件内的原始图片。Nature使用`/full/`而非`/lw685/`缩略图。找不到高清源时如实记录，并实际检查手机显示。
- **先整图实查**：使用已取得的高清原图，先看430 CSS px实际展示，再决定处理。可读且非长图必须整图保留；“组合图、复杂、只讲一个结果、美观、凑图”不是独立裁剪理由。
- **长图优先完整拆分**：高/宽约1.8以上先沿完整面板或连续面板组分段，按原顺序保留全部信息。长图并不授权省略面板；只保留一部分须明确登记为`selected_panels`，不能称为完整`split_panel`。
- **过密图逐级减损**：整图确实不可读时，先尝试较大的连续完整面板组；单面板是最后选择。记录舍弃了哪些面板、为什么更完整展示不可行，以及是否损失必要对照、比较、共享图例或色条。不改变数据、标签、颜色含义，不重绘。
- **裁前裁后双记录**：裁图的`mobile_display.crop_review`引用内部JSON，按原图归集430px整图/处理后截图及SHA-256、具体阅读失败、较完整方案、保留内容及省略面板。仅写“过密/已可读”不充分。现有`image_provenance`、`crop_box`、原图号/面板和像素检查继续保留；公开图注只说明科学内容。
- **必要性与完整性分别审查**：QA既问“为什么必须裁、能否少裁”，也问“是否裁坏”。缺记录、截图不对应、声称整图可读却裁剪、省略面板却登记完整拆分均不得登记QA通过。机器只核对记录/哈希/面板清单，实际可读性及科学比较完整性须实际查看，不能自填标志替代。
- 可读性在选图时先检查430px视口、422px实际图宽；记录当前结论所需的核心文字/坐标/图例、辅助标签和截图。核心信息不可读就换合法原图或阻断。辅助标签仅在不影响本篇解释时可保留为非关键；必要对照、坐标和图例不能为了放行被降级。ND等许可限制不因可读性而放宽。
- 封面同样优先整图，仅必要比例适配允许最小裁剪，并单独记录比例原因。实际许可/ND限制保持不变；来源、许可或可读性不足时停止相应交付。完整原图和面板号不按推文顺序重编号。图后只显示简洁图注。

## 字体与图片显示

- HTML调用 `-apple-system`、`BlinkMacSystemFont`、`Segoe UI`、`PingFang SC`、`Hiragino Sans GB`、`Microsoft YaHei` 和通用无衬线回退，不复制、嵌入、下载或分发系统字体文件。
- 正式文章封面使用论文原图；旧封面生成器和字体已移出插件归档，已有测试PNG仅作离线夹具，不得用于正式文章。
- `digest` 通常用一至两句呈现最有辨识度的发现及与既有认识的差别，不以模糊隐喻制造传播性，作为公众号元数据，并在作者行与研究速览之间以浅灰色导读卡显示一次。先判断每篇论文最有辨识度的阅读入口，再决定用直接陈述、反差、观察、开放问题或自问自答；问句不是默认形式，各形式也不是轮换配额。批量文章需并排检查开头语法、问号位置、句数和两句关系，避免只替换研究对象的同构灰框。研究速览负责紧凑说明怎么做和发现什么，两者不重复同一串样本、模态、步骤和结果事实。
- 段落按完整科学单元组织，不固定数量或字数。同一数据来源和分析目标下的连续步骤、参数或结果合并叙述，短过渡句并入其引出的实质段落。
- 结果优先陈述观察值。群体层面、外部图谱、因果、横断面设计和临床适用范围只在影响理解时进入结果解读，优先直接说明数据来自哪里、分析单位是什么和研究实际测量了什么。
- 合法复用的论文原始栅格图作为来源作品保留，不修改数据和图内文字；移动端裁切或拆分必须记录原图号和面板。
- 字体实际显示可能受微信公众号清洗和终端系统回退影响；插件不得主动请求或分发未登记的商业字体。

## 来源与主张类型

- 内部优先使用 Version of Record，其次为 proof、accepted manuscript、preprint 和其他已核验版本，并记录实际版本。正文统一呈现整合后的方法和结果；只有版本差异影响结果解释时才说明实质差异。
- 核验官方题名、期刊、DOI 和/或 PMID、发表日期及参考文献中的作者信息。
- 每项关键主张都要在后台定位到具体研究材料、页码、章节或图表，但正文不暴露定位或核查过程。
- 后台 `evidence_map` 使用以下 `claim_type`：
  - `direct_result`：论文直接报告的结果；
  - `author_interpretation`：作者对结果的解释；
  - `editorial_explanation`：为说明原文方法或概念所作的解释；
  - `editorial_extension`：受原文约束的有限延伸。
- 这些类型只用于后台质检，不作为正文标签，不把结果组织为“证据链”。

## 来源复用与高风险主张

首次充分阅读后，以`work/research-facts.json`保存来源绑定的精简事实摘要，由构建器生成可读的`work/research-facts.md`，不手写两份。只提取影响核心结论、方法定义或解释的事实：计算对象/维度/归一化与投影、逐分析分母、主要效应、关键交互和阴性、重要敏感性、实际验证层级、观察与解释的区别；逐项保留来源文件、页码、章节、短摘录及清单SHA-256。首读事实先于正文冻结，不能从写完的推文反推一份总是通过的清单。复用已验证版本和既有`evidence_map`/`method_map`，仅回读疑点所需片段，不重复加载全文和全部补充材料。

成稿后在既有科学QA中逐项比较来源事实和正文，判断准确覆盖、合理省略、重要遗漏、错误/过度解释或来源不足。Python只产生带原文/正文定位的候选；概念齐全、摘录存在及`verified`不等于解释正确。语义审校记录具体正文摘录和理由，仅修正影响解释的遗漏/错误；合理省略无需扩写。模型调用和实际Token仅在宿主提供usage时记录，否则标记未测量，不能用篇幅估算账单。内部字段格式见验收文档，不另建写作规则。

仅对本篇涉及的分析检查：分型≠必经阶段；横断面组差≠个体纵向变化；相关/空间/富集/中介≠确定机制；MR结论受工具变量与敏感性假设限制；组内显著性差异≠组间差异，核对交互；交叉验证/内部测试/外部样本/事后亚组≠独立临床验证；指标尺度、分析单位、分母及矩阵定义准确。影响主要结论的阴性结果、不显著交互与敏感性分析不能省略。不要把这些检查写成逐篇十条免责声明，确认错误后直接修正对应句子。

四类`claim_type`继续区分观察、作者解释、编辑说明、有限延伸。未获支持的推断保持`status=needs_review`且不得进入正式交付，不用`verified`代替核验。必要时只在相关映射项增加可选`risk_tags`、`article_locations`；`essential_result=true`用于首次阅读已确认不可遗漏的结果，正文定位必须存在。`scientific-review.json`只产生待核验线索：零命中不等于科学准确；高风险项登记QA时须提供已登记来源的具体位置、原文短摘录和解释，不能仅声明已核实。无法确认则停留待复核。

跨章节比较Digest—研究速览、研究速览—引言、结果—结果解读、结果解读—结语中的同一科学信息；相同词句只是线索，同一主张改写后仍可能重复，阴性与阳性/方向相反的结果不能误删。优先删重复，局部合并或改写，保留正确JSON及图片，不整篇重生成。旧稿正文净增默认≤20%，原则上≤25%；确因技术纠错增加时须说明来源依据，并优先删重复抵消。新稿不设机械总字数、结果数或段落数。

## 客观表达

- 优先使用“研究”、具体数据/模型/结果主语或省略主语。“作者”主要用于有来源的观点和机制解释，减少“论文进行了”“论文发现”“论文提出”。
- 评价性形容词必须有原文比较或判断标准支持。
- 不使用“读者”称呼，不指导受众应该得出什么结论。
- 禁止固定套话，如“30秒读懂”“本文只需记住”“一句话收束”“全文可以收束为”“真正值得带走的是”。
- 控制“不是……而是……”的重复使用。
- “边界、收束、链条、路径、框架、范式、层级、真正、值得”等词仅在属于准确来源术语时保留。
- 一个句子包含多个逻辑转折且超过约 60 个中文字符时拆分表达。
- 不使用“该模块”“本模块”“该步骤输出”“分析链”“证据链”等技术报告式元语言。
- 全文减少“这些结果共同表明”“这一发现进一步说明”“值得注意的是”“更重要的是”“总体而言”“综合来看”“这一发现提示我们”“提供了新的视角”“核心价值在于”“尚待检验的是”等模板化表达。能用具体研究对象、指标或结果作主语时，优先删除引导语，不作同义替换。
- 不要求每个段落有总结句。逐段检查最后一句；若只是在重复、评价、升华、裁决或泛泛展望，删除后信息仍完整，则优先删除。
- 不统一段落长度和小标题数量，不机械套用“发现—意义—局限—未来”结构。
- 结果解读每段增加具体解释：联系不同发现、说明空间或统计关系、区分分析层面或澄清实际误读；不靠重述结果或叠加局限增加篇幅。结语可为一段，只有新增论文特异信息时才谈研究设计；不用“研究设计上的启发在于”“方法学上的启发在于”“对MRI研究，较有用的是”“对计算神经影像研究”等固定开头。

## 成稿前检查

1. 必需一级标题及顺序是否准确，是否错误生成了独立“方法启示”。
2. 论文题名、标识符、日期、样本、方向、统计量和图号是否与来源一致。
3. 直接结果、作者解释和编辑说明是否准确区分。
4. 结果是否构成全文主体，是否被方法或泛泛评论淹没。
5. 仅阅读标题、研究速览、结果小标题和结语，是否能够复述论文研究了什么、使用了什么核心方法、发现了什么。
6. 研究速览、引言和结果是否重复完整结论；方法是否堆积非关键参数；结果是否堆积次要统计量。
7. 是否存在模板化语言、过多评价、泛化建议，或把相关、空间关系和富集写成因果机制。
8. 结果解读是否具有解释增量而非复述结果或罗列未实施分析；结语是否简洁说明新增认识，方法层评论若出现是否确有新增信息且没有固定启示句式。
9. 图片来源、许可和移动端策略是否记录齐全，公开HTML是否只显示简洁图注。
10. HTML是否只调用设备字体而不分发字体文件，正式文章封面是否来自本篇原图。
11. `publication_mode` 是否仍为 `draft_only`。
12. 修改旧稿时，用户未授权修改的章节是否与输入保持一致。

## 统一输出与版本复核

`scripts/prepare_article.py`是固定JSON和原图的成品生成入口，不在复现时重新检索、写稿或调整版式。只有`preview.html`内嵌完整图片；`article.html`保留为轻量入口，图片检查页引用本地原图，上传片段为`wechat-upload.html`。证据、方法、图片清单均从同一JSON生成，不逐篇另写渲染器。

结构规则只维护在JSON Schema；Python校验器在结构通过后检查科学写作、来源及图片等业务约束。`LOCAL_CHECKS_PASSED`不代表完成科学、许可或视觉复核。全部实际复核通过后，使用统一入口的`--record-qa`及三类真实复核说明生成`qa-review.json`，绑定成稿清单哈希；未完成的复核不得以命令代替。

登记成稿、用户批准、实际保存前都检查同一JSON、HTML、图片和复核记录。修改后旧QA/批准失效，需重建并重做受影响的检查。批准是用户对具体成稿的授权，不由机器检查自动产生。
