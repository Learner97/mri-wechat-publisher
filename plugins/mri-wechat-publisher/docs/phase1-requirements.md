# 第一阶段需求与边界

## 目标

建立最小 B 级闭环：结构化科学文章经过质检和公众号排版后，自动保存到公众号草稿箱，由用户人工预览和发表。

## 必须满足

1. 新文章采用“研究速览、引言、方法、结果、结果解读、结语”六部分结构；方法认识只在确有可迁移设计时自然并入结语，不另设方法启示。
2. 标题、研究速览、作者、正文、参考文献和图片元数据可追溯。
3. 默认输出微信公众号兼容 HTML。
4. 草稿连接器支持 API 主通道和已登录浏览器备用通道。
5. 任何自动化都不得点击或调用“发表”“发布”或“群发”。
6. 未通过质检的文章不得进入草稿箱。
7. AppSecret 不得进入 Git、日志、测试夹具或聊天记录。
8. 公开HTML只显示简洁图注；图片来源与许可必须在内部元数据中保留。
9. 插件生成HTML和封面不得主动请求或分发未登记的商业字体。

## 第一阶段不做

- 每日 17:00 文献推荐；
- 次日 09:30 自动交稿；
- 自动发表或群发；
- 阅读、点赞、转发等运营数据采集；
- 无人值守的长期服务器部署。

## B 级验收定义

标题含“【自动化测试—请勿发表】”的测试文章由程序自动保存到公众号草稿箱，用户能在后台打开并预览；全流程没有触发发表，日志不包含凭据。
